# custom-modules — 개인 기능 모듈

엔진 소스(`packages/`)를 고치지 않고 기능을 붙이기 위한 폴더입니다. 마리나라를 업데이트해도 이 폴더와
설치된 모듈은 덮어써지지 않습니다.

## 구조

| 경로                              | 내용                                                                           |
| --------------------------------- | ------------------------------------------------------------------------------ |
| `mari-kit/`                       | 패키지 하나(Mari Kit)에 기능을 모읍니다. 기능마다 켜고 끌 수 있습니다          |
| `mari-kit/src/server.mjs`         | 서버 쪽: 라우트(`/api/mari-kit/…`), 패키지 저장소, 생성마다 프롬프트에 붙는 글 |
| `mari-kit/src/client.js`          | 화면 쪽: 채팅 설정의 Mari Kit 칸. 프레임워크 없이 순수 DOM이라 수 KB입니다     |
| `mari-kit/agents.json`            | 채팅마다 켜는 스위치 역할의 에이전트(`execution: "feature"`, 모델 호출 없음)   |
| `mari-kit/manifest.template.json` | 패키지 정보. 파일 해시는 빌드할 때 채웁니다                                    |
| `scripts/build.mjs`               | `dist/mari-kit/<버전>/`에 파일과 해시가 든 `manifest.json`을 만듭니다          |
| `scripts/install.mjs`             | 빌드한 모듈을 데이터 폴더의 `capability-packages/`에 넣고 등록합니다           |
| `scripts/check.mjs`               | 빌드 + 엔진 스키마로 검사 + 도우미 함수 확인                                   |

엔진과는 공식 패키지 기능(Capability API)으로만 연결합니다. 엔진은 패키지 파일을 읽을 때마다 해시를
다시 확인합니다.

## 설치

1. 마리나라를 끕니다.
2. `node custom-modules/scripts/install.mjs` — 데이터 폴더가 기본 위치(`packages/server/data`)가 아니면
   `--data-dir <경로>`를 붙이거나 `DATA_DIR`을 지정합니다.
3. 마리나라를 다시 켭니다.
4. 쓰려는 채팅에서 **채팅 설정 → 에이전트**를 켜고 **Mari Kit**를 추가합니다. 그 채팅의 설정에 Mari Kit 칸이
   생기고, 여기서 기능을 켭니다.

Mari Kit를 추가하지 않은 채팅에는 아무것도 넣지 않고, 모델도 부르지 않습니다.

채팅 설정의 에이전트 칸에는 Mari Kit를 추가하면 "추가 호출 약 1번/턴"이 표시되지만, 엔진이 에이전트 수로
어림한 값입니다. Mari Kit 에이전트는 `execution: "feature"`라서 파이프라인 호출을 하지 않습니다. 가짜 AI 서버로
RP 한 턴을 생성해 세어 본 결과, 추가하지 않은 채팅과 추가한 채팅 모두 AI 요청은 1번이었습니다.

## 점검

`node custom-modules/scripts/check.mjs` — 모듈을 빌드하고, 지금 엔진의 스키마로 `manifest.json`·`agents.json`을
검사하고, 서버 쪽 도우미 함수를 확인합니다. 엔진을 업데이트한 뒤에도 실행해 호환되는지 봅니다
(`pnpm build:shared`를 한 번 해 둬야 합니다).

엔진을 업데이트한 뒤에도 모듈은 그대로 남습니다. 모듈을 고친 뒤에는 2~3번만 다시 합니다.

## 데이터

- 설정과 기능 데이터는 엔진의 패키지 저장소(`capability_documents`)에 `mari-kit` 이름으로 저장됩니다.
- 화면 코드는 한 파일이고, 바뀌지 않았으면 브라우저가 다시 받지 않습니다(ETag → 304).

## 기능 계획

| 순서 | 기능                                                           | 비용 원칙                                         |
| ---- | -------------------------------------------------------------- | ------------------------------------------------- |
| 1    | TTS: 감정 지시·화자 태그 지침, 대사별 재생, 발음(성·이름 분리) | 메인 AI가 같은 답장에 태그를 씀. 추가 AI 요청 0번 |
| 2    | 번역: 프리셋·단어장·말투                                       | 번역 요청 1번에 프리셋·단어장을 붙임              |
| 3    | Convo 날씨                                                     | 날씨·기온만 프롬프트에 넣음. AI 요청 0번          |
| 4    | 기억                                                           | 아래 설계                                         |

### TTS (구현됨)

쓰는 법: Mari Kit를 추가한 채팅의 설정에서 **TTS**를 켭니다. 처음 켤 때 화면 표시 규칙(정규식 스크립트 3개)이
설치됩니다. 음성 자체는 엔진의 **설정 → 연결 → 음성(TTS)**을 그대로 씁니다. 2.5.2의 **RP 화자 추출기**는 끄세요.
켜 두면 답장마다 AI 요청이 다시 2번이 됩니다.

| 부분        | 동작                                                                                                                                                                                                                                                        |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 지침        | RP에서만 생성 때 `<voice_markup>` 지침을 붙입니다. 메인 AI가 같은 답장에 대사를 `<audio_character id="…">` / `<audio_persona id="…">`로 감싸고, 대사 맨 앞에 영어 감정 지시 `[low, amused]`를 하나 씁니다. 추가 AI 요청 0번                                 |
| 화면        | 표시 전용 정규식 스크립트가 태그를 `<span class="mk-line …">`로, 대사 맨 앞의 감정 지시를 지웁니다. 저장된 메시지는 바뀌지 않습니다                                                                                                                         |
| 대사별 재생 | 각 대사 뒤에 ▶ 버튼. 누르면 메시지 원문에서 그 대사를 찾아 엔진 TTS로 재생합니다(캐시·입 모양 연동은 엔진 그대로). 재생 중 ■로 멈춤                                                                                                                         |
| 보이스      | 캐릭터별 보이스 모드면 그 화자의 보이스, 없으면 기본 보이스                                                                                                                                                                                                 |
| 감정        | 대사 앞 감정 지시를 TTS의 `tone`으로 보냅니다(OpenAI 계열은 지시문, ElevenLabs는 오디오 태그)                                                                                                                                                               |
| 발음        | 캐릭터·페르소나 편집창의 **발음 표기 이름**을 씁니다. 이름과 발음의 단어 수가 같으면 단어별로도 바꿉니다: `쿠가 테루노리` → `kuga terunori`이면 `테루노리가` → `terunori가`, `쿠가` → `kuga`. 라틴 이름은 단어 경계를 지킵니다(`IV`는 `IVY` 안에서 안 바뀜) |

한계

- 버튼을 붙일 공식 자리가 없어, 화면의 `[data-message-id]` 안의 `span.mk-line`을 찾아 붙입니다. 엔진 화면 구조가
  크게 바뀌면 고쳐야 합니다.
- 태그가 붙은 메시지는 엔진의 HTML 표시 경로를 타서, 대사에 칠해지던 대사 색(굵게·색)이 빠집니다.
- 단어 수가 다른 이름(애칭 등)은 지금은 단어별로 바뀌지 않습니다. 필요하면 별명 목록을 추가합니다.
- Convo에는 지침을 넣지 않습니다(메시지가 이미 화자별이라 엔진 기본 TTS로 충분).

### 번역 (구현됨)

쓰는 법: Mari Kit를 추가한 채팅의 설정에서 **번역**을 켜면 그 아래에 번역 칸이 생깁니다. 채팅 설정 → 번역의
공급자가 **AI**여야 합니다(DeepL·Google은 지시문을 쓰지 않습니다).

| 부분          | 동작                                                                                                                                                                                 |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 프리셋        | 응답 번역·입력 번역에 각각 고릅니다. "채팅 설정 유지"는 채팅에 원래 있던 번역 지시문을 바탕으로 씁니다. 프리셋은 ME-personal에 있던 「번역 프리셋·단어장」 1.6.4의 16개 그대로입니다 |
| 단어장        | 한 줄에 하나 `원문 = 번역 # 메모`. 응답 번역에는 원문 → 번역, 입력 번역에는 번역 → 원문으로 들어갑니다                                                                               |
| 말투          | 응답 번역에만 들어갑니다                                                                                                                                                             |
| 세계관        | 양쪽에 들어갑니다                                                                                                                                                                    |
| 저장하고 적용 | 위 내용을 합쳐 채팅의 번역 지시문(응답·입력) 칸에 씁니다. 엔진의 수동 번역 버튼과 자동 번역이 그대로 씁니다. **번역할 때 추가 AI 요청 없음**                                         |
| 원래대로      | 처음 적용하기 전의 채팅 지시문을 되돌립니다. Mari Kit의 메모는 남습니다                                                                                                              |
| 자동 수집     | 단어장 자동 수집·말투 자동 정리·세계관 정리. **누를 때만** 번역 연결로 AI 요청 1번. 카드·페르소나·채팅에 켜진 로어북·최근 메시지 40개를 읽고, 결과를 칸에 채웁니다(저장해야 적용)    |

한계

- 엔진은 번역 지시문을 5,000자까지만 받습니다. Mari Kit는 4,800자 안에 맞추고, 넘치면 세계관 → 단어장 아래쪽
  항목 → 말투 순서로 줄이고 상태 줄에 무엇을 뺐는지 표시합니다. 가장 긴 프리셋이 2,602자라 단어장·말투에 약
  2,200자가 남습니다.
- 단어장은 메시지마다 골라 넣지 않고 전부 넣습니다(엔진 번역 요청에 끼어들 자리가 없어서). 그래서 길이 제한이
  있습니다.
- 「번역 프리셋·단어장」 확장의 문단별 번역 보기·원문 대조·이전 대화 Context는 넣지 않았습니다(화면 작업 또는
  엔진 수정이 필요).
- 채팅 설정에서 번역 지시문을 직접 고치면 상태 줄에 표시되고, 다시 적용하면 고친 지시문을 바탕으로 씁니다.

### 기억 설계 (확정)

- 정리: **버튼으로만** 시작. 묶음당 API 모델 호출 1번. 원문 문장에 `[n.k]` 번호를 붙여 보내고, 대사는 번호로만
  받아 서버가 원문에서 가져옵니다. 화자 판정은 규칙으로만 합니다.
- 저장: 장면·대상별 사실(누가 아는지 포함)·끝나지 않은 일·호칭. 검증을 모두 통과해야 한 번에 저장하고, 메시지
  지문으로 중복 정리를 막습니다. 묶음 단위 되돌리기.
- 압축: 장면이 쌓이면 오래된 장면을 장 요약으로 묶습니다(그때만 1번).
- 회상: 답장마다 **모델 호출 0번**. 정리 때 함께 뽑은 키워드·별칭으로 고릅니다(임베딩은 처음엔 끔).
- 주입 상한 **5천 토큰**. 순서: 장 요약 → 끝나지 않은 일·고정 → 지금 장면 인물 상태 → 관련 장면(최대 3).
  이번 턴 화자가 모르는 사실은 빼고, 여러 명이 함께 말하면 "(○○는 모름)"을 붙입니다.
- 빈틈 보완: 정리 안 된 메시지 수 표시, 원문이 바뀐 묶음 표시·다시 정리, 채팅 분기·삭제 처리, 형식 오류는
  한 번만 다시 요청.
- 기존 ME-personal 통합 기억은 가져오지 않고 새로 시작합니다.
